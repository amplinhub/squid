# Перенос GROW UP (Abyss Squid) с Game Maker 8 на JavaScript + three.js

Цель: та же игра в браузере на телефоне и компьютере, публикация через GitHub Pages, онлайн-таблица рекордов на Google Sheets + Apps Script.

Исходник сейчас: 30 файлов GML, около 9400 строк, плюс генераторы графики и звука на C# (`tools/Art.cs`, `tools/SoundGen.cs`). Почти вся графика процедурная: модели строятся кодом, поэтому переносить можно 1-в-1, без 3D-редактора.

---

## 1. Технический стек

| Часть | Выбор | Почему |
|---|---|---|
| Язык | JavaScript (ES-модули), без сборщика | На компьютере нет Node.js. GitHub Pages отдаёт модули как есть. Сборщик (Vite) можно добавить позже. |
| 3D | three.js r16x, копия лежит в репозитории (`vendor/three.module.js`) | Не зависим от CDN, игра работает даже при недоступности CDN |
| Интерфейс | HTML + CSS поверх `<canvas>` | Адаптивность (flex/grid, `clamp()`, медиазапросы), чёткий текст на любом экране |
| Сонар, мини-элементы HUD | 2D canvas поверх 3D | Быстро, без перерисовки DOM каждый кадр |
| Звук | Web Audio API | Громкость, повтор, приглушение «под водой» фильтром |
| Сохранения | `localStorage` | Настройки, бестиарий, прогресс персонажей |
| Рекорды | Google Sheets + Apps Script (Web App) | Как вы хотите, бесплатно |
| Хостинг | GitHub Pages | Статика из репозитория |
| Тесты | Playwright (позже, понадобится Node.js) | Перенос нынешнего автотеста: сценарий, снимки, замер FPS |

## 4. Графика на three.js (что станет лучше)

Базово — тот же стиль low-poly с цветом граней, затем по пресетам качества:

1. **Туман и цвет воды по глубине** — как сейчас.
2. **Каустика** — шейдер, проецирующий узор сверху на всё: дно, рыб, игрока.
3. **Поверхность воды снизу** — шейдер с колыханием и бликами.
4. **Лучи света** — объёмные полупрозрачные конусы.
5. **Bloom** — свечение медуз, анчоусов, фонаря удильщика, радиоактивных бочек (только на среднем/высоком качестве).
6. **Анимация существ в шейдере**: изгиб тела рыбы, колыхание водорослей, пульсация медуз — работает на видеокарте, тысячи объектов без нагрузки на процессор.
7. **Инстансинг**: одинаковые рыбы одного вида (косяки) рисуются одним вызовом.
8. **Небо в меню**: градиент + солнце + облака + отражения на воде шейдером.

## 5. Производительность (особенно на телефоне)

- Пресеты качества: «Низкое / Среднее / Высокое» + **авто-выбор по FPS** в первые секунды (уже есть в игре — переносим).
- Ограничение плотности пикселей: `renderer.setPixelRatio(min(devicePixelRatio, 1.5))` на телефонах.
- Отсечение невидимого — three.js делает сам, плюс наше отсечение по туману и размеру.
- LOD декора (дальнее кольцо чанков без мелкого декора) — переносим.
- Генерация чанков в Web Worker, геометрия передаётся без копирования (transferable).
- Пулы объектов для частиц, без создания мусора каждый кадр.
- Пауза при сворачивании вкладки (`visibilitychange`).

## 6. Управление

| Устройство | Схема |
|---|---|
| Компьютер | Как сейчас: W/S, A/D/стрелки, вверх/вниз, Shift — рывок, F — способность, Esc — пауза; мышь в меню |
| Телефон | Левый виртуальный стик — поворот и плавание (вверх/вниз по стику), правая сторона — кнопки «Рывок» и «Способность», кнопка паузы сверху |
| Геймпад (по желанию) | Gamepad API |

Тач-элементы показываются только при сенсорном вводе. Учитываются вырезы экрана (`env(safe-area-inset-*)`).

## 7. Адаптивный интерфейс

- Вёрстка от размера экрана: панели и шрифты через `clamp()`, медиазапросы для узких экранов.
- Альбомная ориентация на телефоне — основная; в книжной показываем подсказку «поверните телефон» (или поддерживаем — см. вопросы).
- Полноэкранный режим (Fullscreen API) по кнопке; на iPhone полноэкранного API нет — делаем «добавить на экран Домой» (PWA).
- Стиль: латунь, морское стекло, канаты — тот же, но в векторе (CSS/SVG), чёткий на любом экране.

## 8. Онлайн-рекорды: Google Sheets + Apps Script

**Таблица** `Leaderboard`: дата, имя, длина, звание, персонаж, время игры, версия игры, id игрока (случайный, хранится в localStorage).

**Apps Script (Web App)**:
- `doGet(e)` — отдаёт топ-N (JSON), с кешем `CacheService` на 30–60 с, чтобы не упираться в квоты.
- `doPost(e)` — принимает рекорд. Тело запроса отправляется как `text/plain` (обходит CORS preflight, который Apps Script не умеет).
- `LockService` — одновременные записи не ломают таблицу.
- Проверки: длина имени, фильтр запрещённых слов, правдоподобные значения (размер не больше возможного за время игры), не чаще одной отправки в N секунд с одного id.
- Развёртывание: «Развернуть → Веб-приложение → Выполнять от моего имени, доступ: все». URL вставляется в `js/net/leaderboard.js`.

**Честно о защите**: в браузерной игре клиент можно подделать, поэтому полностью защитить таблицу невозможно. Защищаемся проверками правдоподобия и лимитами. При необходимости можно добавить ручную модерацию в таблице: флажок «скрыть».

**Если сеть недоступна** — рекорд сохраняется локально и отправляется позже.

## 9. Публикация через GitHub Pages

1. Репозиторий (ваш), ветка `main`, папка корня — сайт.
2. Settings → Pages → Deploy from branch → `main` / root.
3. Адрес: `https://<логин>.github.io/<репозиторий>/` — все пути в игре относительные.
4. Кеширование: версия игры в имени (`?v=…`) у JS/CSS, чтобы игроки сразу получали обновления.
5. (По желанию) PWA: манифест + service worker → установка на телефон, работа офлайн.

## 11. Риски

- **iPhone/Safari**: звук только после первого касания, нет Fullscreen API, ограничения памяти WebGL — тестируем рано.
- **Слабые Android-телефоны**: держим «Низкое» качество с меньшей дальностью и без bloom.
- **Квоты Apps Script**: при большом числе игроков — кеш и редкие запросы.
- **Подделка рекордов**: только проверки правдоподобия (см. раздел 8).
- **Node.js не установлен**: для автотестов Playwright понадобится установить Node.js (сама игра работает без него).

## 12. Принятые решения (ответы владельца)

- Репозиторий: `amplinhub`, код отправляю я через git.
- Node.js можно ставить (автотесты Playwright).
- Графику улучшаем сразу, но без потери FPS; стиль low-poly сохраняем.
- Языки: русский и английский. Заставка AMPLIN остаётся. Версию на GM8 больше не развиваем.
- Ориентации: альбомная и книжная (интерфейс и камера перестраиваются).
- Телефон: левый стик — поворот, всплытие, погружение; справа кнопки «Плыть», «Рывок», «Способность». Целевое устройство — Google Pixel 11.
- PWA не нужен.
- Рекорды: очки, одна общая таблица, топ-100 + место игрока внизу, если он не в топе; хранится только лучший результат.
- Аккаунт: имя + PIN из 4 цифр при первом запуске, вход с другого устройства.
- Таблица: «Squid» (Google Sheets), заполняю я; защита от подделки — простая, главное — бережная нагрузка на сервер.
- Адрес — GitHub Pages. Нужна статистика игроков. Сроков нет, приоритет — качество и проверка.

### Уточнения (второй раунд)
- Репозиторий `amplinhub/squid` (публичный, для GitHub Pages).
- Apps Script разворачивает владелец по инструкции; таблица закрывается от доступа по ссылке.
- Синхронизируется весь прогресс (рекорд, персонажи, бестиарий, задания) по имени + PIN.
- Имя: кириллица, латиница, цифры; уникальное; сменить нельзя. Забытый PIN не восстанавливается.
- Регистрация — при первом рекорде (до этого гость).
- В таблице рекордов виден персонаж; очки у всех персонажей считаются одинаково (вариант «Охотник»).
- Статистика: всё перечисленное (игроки, заходы, время, устройство, язык, причины смерти, съедаемые виды), без уведомления игрока; позже — просмотр в игровом аккаунте владельца.
- Язык — по браузеру + переключатель. Фоновая музыка — добавить. Баланс — как в GM8. Браузер — Chrome.
